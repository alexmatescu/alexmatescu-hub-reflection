# Metadata și citarea AI: ce poate demonstra o citare identică și unde începe inferența

**În cazul documentat aici, un sistem AI a citat textual o formulare publicată în metadata de pe delamatescu.ro. Acest exact match este o evidență puternică că textul respectiv a intrat în lanțul de regăsire sau de generare folosit pentru răspuns. Nu demonstrează însă, de unul singur, că modificarea metadata a cauzat apariția citării, că sistemul a extras textul direct din câmpul `meta description` în acel moment sau că aceeași tehnică va produce același rezultat pe alte motoare. Studiul este util tocmai pentru această diferență: putem observa sursa textuală, dar trebuie să fim mai prudenți când descriem mecanismul și cauzalitatea.**

Aceasta este miza corectă a documentului.

Nu este un „hack de metadata”. Este un studiu despre **atribuirea sursei într-un sistem AI** și despre cât de ușor poate fi confundată o observație reală cu o explicație algoritmică nedemonstrată.

## Ce s-a întâmplat

Înainte de modificarea metadata, întrebările folosite în test nu produceau o descriere echivalentă a identității profesionale.

După modificare, un răspuns AI a folosit **textual** formularea publicată pe delamatescu.ro.

În versiunea inițială a acestui articol, această observație a fost interpretată greșit ca o parafrază. Cazul real este mai puternic: a existat **reproducere cuvânt cu cuvânt** a textului publicat.

Această corecție schimbă nivelul de evidență.

Un exact match suficient de distinctiv este mult mai puternic decât o asemănare semantică. El susține că textul respectiv a fost disponibil sistemului printr-un mecanism de retrieval, indexare, caching, integrare sau altă sursă care conținea acea formulare.

Totuși, există trei afirmații diferite și ele nu trebuie confundate:

1. **Textul a apărut identic în răspuns.** — observație directă.
2. **Textul publicat pe site a fost una dintre sursele disponibile sistemului.** — inferență puternică, dacă formularea este suficient de distinctivă și nu apare în alte surse.
3. **Modificarea metadata a cauzat apariția răspunsului și sistemul a citit direct câmpul respectiv.** — nu poate fi demonstrat dintr-un singur before/after.

Această separare este esențială pentru un studiu GEO/AEO credibil.

## Ce poate demonstra un exact match

O citare textuală identică poate funcționa ca **marker de atribuire**.

Forța dovezii crește dacă:

- formularea este suficient de distinctivă;
- înainte de publicare nu apare în alte rezultate web cunoscute;
- este publicată într-o singură locație controlată;
- există un timestamp;
- răspunsul AI apare după publicare;
- răspunsul citează sau linkuiește explicit URL-ul controlat;
- experimentul este repetat pe același set de interogări.

În aceste condiții, reproducerea exactă este evidență puternică pentru faptul că textul a fost disponibil sistemului.

Dar exact match-ul **nu identifică automat ruta tehnică**. OpenAI documentează că ChatGPT Search poate obține informații prin crawling direct și prin furnizori terți de căutare; dacă o pagină este blocată, OpenAI poate în anumite cazuri cunoaște totuși URL-ul și titlul prin alte surse.[^openai-publishers]

De aceea, chiar atunci când sursa textuală este foarte probabil identificată, traseul exact `site → crawler → index → răspuns` nu trebuie inventat dacă nu este observabil.

## Fraza-trasor: marker experimental, nu probă absolută

Din cazul de mai sus rezultă o tehnică utilă, dar trebuie definită riguros.

O **frază-trasor** este o formulare distinctivă introdusă deliberat într-o locație controlată pentru a testa dacă textul reapare ulterior într-un răspuns.

Nu este o „dovadă matematică” de retrieval.

Este un **marker experimental de atribuire**.

### Condiții recomandate

Pentru un test riguros:

1. verifică înainte de publicare că formularea nu apare deja pe web;
2. public-o într-o singură locație controlată;
3. păstrează data și ora publicării;
4. nu modifica alte elemente în același timp dacă testezi efectul unui singur câmp;
5. folosește un set fix de interogări;
6. rulează fiecare interogare de mai multe ori;
7. notează motorul, modul de search și sursele afișate;
8. separă `exact match`, `partial match`, `parafrază` și `citare explicită a URL-ului`;
9. folosește cel puțin un control negativ;
10. repetă testul după ce pagina a fost recrawlată sau reindexată, dacă acest lucru poate fi observat.

O reproducere exactă are o valoare probatorie mai mare decât o parafrază. O parafrază, singură, nu trebuie tratată ca identificare a sursei.

## Ce spune studiul despre metadata — și ce nu spune

Studiul arată că textul din metadata poate ajunge într-un răspuns AI.

Nu demonstrează că:

- meta description este un factor direct de ranking sau citare AI;
- `<title>` este „cel mai puternic semnal” pentru un motor AI;
- JSON-LD `Person` determină citarea unei persoane;
- ordinea cuvintelor din meta description este un factor algoritmic;
- un crawler care vede body-ul va prefera metadata;
- toate sistemele AI procesează metadata în același mod.

OpenAI publică recomandări despre accesul OAI-SearchBot și despre includerea conținutului în summaries și snippets, dar nu publică o regulă care să declare `meta description` drept factor de citare.[^openai-publishers]

Prin urmare, afirmația corectă este:

> **Metadata este o parte accesibilă și descriptivă a documentului HTML și poate fi folosită de sisteme de search sau retrieval, dar efectul fiecărui câmp asupra citării AI nu este public documentat ca factor individual.**

## Corecția tehnică față de studiul despre Lovable

Versiunea inițială a acestui articol presupunea că requestul generic care primea doar shell-ul React reproducea condiția în care operează „majoritatea crawlerelor AI”.

Această presupunere nu mai este susținută.

Documentația Lovable verificată la **10 august 2026** spune că proiectele Lovable rulează pe două stive:[^lovable-seo]

- aplicațiile noi create după **13 mai 2026** folosesc TanStack Start cu server-side rendering, cu excepțiile documentate de Lovable;
- proiectele mai vechi React + Vite folosesc prerendering pe URL-urile publice pentru motoare de căutare, social-preview bots și AI crawlers;
- vizitatorii umani continuă să primească experiența SPA pe proiectele vechi;
- Lovable declară că ambele stive sunt proiectate să ofere HTML crawlabil motoarelor de căutare și motoarelor AI.

Important: documentația Lovable curentă spune că **proiectele React + Vite existente nu pot migra momentan la TanStack Start**; ele beneficiază de prerendering automat.[^lovable-seo]

Această informație este volatilă și trebuie reverificată înaintea unei actualizări viitoare a articolului.

### Ce demonstrează testul `curl`

Dacă un request generic primește numai shell-ul și metadata, putem afirma doar:

> **acel request a primit numai acea reprezentare.**

Nu putem deduce automat că OAI-SearchBot, PerplexityBot, Googlebot sau un crawler pe care Lovable îl tratează separat primește același HTML.

Prin urmare, faptul că exact match-ul a apărut într-un răspuns AI **nu poate fi folosit ca dovadă că restul site-ului era inaccesibil**.

Este posibil ca sistemul să fi avut acces la o versiune pre-randată și să fi preferat textul concis din metadata. Este posibil și ca textul să fi ajuns printr-un alt mecanism de retrieval. Cazul observat nu permite separarea acestor variante.

## Ce face, verificabil, fiecare element

Nu există o ierarhie publică universală a „greutății metadata pentru AI”. Tabelul de mai jos descrie numai roluri documentate sau tehnice verificabile.

| Element | Ce se poate afirma verificabil |
|---|---|
| `<title>` | Descrie pagina. Google îl folosește ca una dintre mai multe surse pentru generarea title link-ului. |
| `meta description` | Google o poate folosi pentru snippet atunci când consideră că descrie pagina mai bine decât textul extras din conținut. |
| JSON-LD | Oferă o reprezentare structurată, machine-readable, a informațiilor despre pagină și entități. |
| `og:title` | Este folosit pentru social previews și este una dintre sursele pe care Google le poate folosi la generarea title link-urilor. |
| `<h1>` și alte heading-uri | Google le poate folosi, împreună cu alte elemente vizibile, la generarea title link-ului. |
| `canonical` | Este un semnal puternic pentru alegerea URL-ului canonical între pagini duplicate sau foarte similare. |
| `lang` | Declară limba documentului pentru browsere, tehnologii asistive și alte procesoare HTML; Google Search spune explicit că detectează limba din text și nu se bazează pe atributul `lang`. |

Surse: Google Search Central.[^google-title][^google-snippet][^google-structured][^google-canonical][^google-lang]

### Nu există limite fixe de 60 și 155 de caractere

Versiunea inițială folosea drept limite:

- aproximativ 60 de caractere pentru `<title>`;
- aproximativ 155 de caractere pentru `meta description`.

Google spune explicit că **nu există o limită fixă** pentru niciunul dintre aceste câmpuri. Title link-urile și snippets sunt trunchiate după nevoie, de obicei în funcție de spațiul disponibil pe dispozitiv.[^google-title][^google-snippet]

Prin urmare, nu există nici o limită tehnică justificată de „aproximativ 30 de cuvinte utile”.

Recomandarea defensabilă este mai simplă:

> scrie title și meta description concise, descriptive și specifice paginii, fără a trata 60/155 drept praguri algoritmice.

## Structured data: utilă, dar nu „fără ambiguitate”

JSON-LD poate ajuta un sistem să proceseze informații structurate despre pagină și entități.

Google spune că structured data îi oferă indicii explicite despre sensul unei pagini și recomandă JSON-LD ca format atunci când implementarea îl permite.[^google-structured]

Dar structured data:

- nu este singurul loc în care trebuie declarată identitatea;
- nu garantează afișarea sau rankingul;
- nu trebuie să descrie informații inexistente sau ascunse față de utilizator;
- trebuie să fie reprezentativă pentru conținutul paginii.[^google-sd-policies]

Formulare corectă:

> **JSON-LD este un strat machine-readable suplimentar care poate clarifica entități și relații deja susținute de conținutul real al paginii.**

Nu există o sursă oficială care să confirme că `Person` JSON-LD produce direct citări în ChatGPT, Perplexity sau alte sisteme AI.

## Cum scrii metadata clară pentru oameni, Search și sisteme de retrieval

Secțiunea nu trebuie prezentată ca rețetă pentru „a obține citări”.

### Folosește un title descriptiv și specific

Google recomandă `<title>` distinct și descriptiv pentru fiecare pagină și evitarea textului vag sau repetitiv.[^google-title]

### Scrie o meta description relevantă pentru pagina respectivă

Google poate folosi meta description ca snippet atunci când consideră că oferă un rezumat mai bun decât alte fragmente ale paginii. Meta description trebuie să fie specifică paginii și nu trebuie tratată ca text obligatoriu afișat.[^google-snippet]

### Pune informația principală devreme pentru claritate, nu pentru un presupus algoritm

Versiunea inițială afirma că „primul substantiv devine statistic atributul dominant”. Nu există o sursă care să susțină această afirmație.

O recomandare editorială rezonabilă este doar:

> **pune identitatea sau tema principală suficient de devreme încât descrierea să fie clară chiar dacă este scanată rapid sau trunchiată vizual.**

Aceasta este o recomandare de scriere, nu un factor AI demonstrat.

### Evită keyword stuffing

Google recomandă titluri concise, descriptive și fără repetarea inutilă a acelorași termeni.[^google-title]

### Folosește structured data numai pentru informații reale

Structured data trebuie să corespundă informației vizibile și să nu inducă în eroare.[^google-sd-policies]

### Păstrează metadata specifică fiecărei rute

Lovable recomandă metadata unică per pagină și include verificări SEO/AEO pentru metadata, canonicalizare și crawlabilitate.[^lovable-seo]

## Cum verifici ce HTML primește requestul

`curl` este util pentru inspectarea răspunsului HTTP brut.

```bash
curl -s https://exemplu.ro > /tmp/page.html
grep -i '<title' /tmp/page.html
grep -i 'meta name="description"' /tmp/page.html
grep -i 'application/ld+json' /tmp/page.html
```

Acest test răspunde la:

> „Ce conține HTML-ul primit de acest request?”

Nu răspunde automat la:

> „Ce primește fiecare crawler AI?”

Pentru un proiect Lovable vechi, documentația platformei spune că crawlerele de search și AI primesc conținut pre-randat pe URL-urile publice, în timp ce experiența SPA rămâne pentru utilizator.[^lovable-seo]

## Cum măsori efectul fără să inventezi cauzalitatea

Un singur before/after nu demonstrează că schimbarea metadata a cauzat apariția citării.

Pentru un experiment mai bun:

- definește înainte setul de interogări;
- salvează răspunsurile și sursele;
- rulează fiecare interogare repetat;
- modifică un singur element;
- verifică dacă schimbarea a fost recrawlată/reindexată atunci când instrumentele permit;
- repetă testele;
- separă exact match-ul de parafrază;
- notează dacă există citare explicită a URL-ului;
- folosește control negativ.

Google recomandă aceeași logică generală pentru măsurarea efectului structured data: test înainte/după pe pagini comparabile, validarea implementării și urmărirea performanței în timp.[^google-structured]

Pentru sisteme generative, această disciplină este și mai importantă deoarece răspunsurile pot varia între rulări.

## Ce poate fi concluzionat din cazul delamatescu.ro

### Observație confirmată în studiul de caz

După publicarea textului, un răspuns AI a reprodus **cuvânt cu cuvânt** formularea de pe delamatescu.ro.

### Inferență rezonabilă

Dacă formularea era suficient de distinctivă și nu era prezentă în alte surse, exact match-ul constituie o evidență puternică că textul publicat a fost disponibil sistemului.

### Ce nu poate fi demonstrat numai din observație

Nu se poate demonstra că:

- meta description a fost singura sursă;
- crawlerul a extras direct acel câmp în momentul răspunsului;
- restul paginii era inaccesibil;
- modificarea metadata a fost singura cauză;
- aceeași schimbare ar produce același efect pe alt motor sau alt site.

Această distincție este rezultatul principal al studiului.

## Concluzia

Cazul nu demonstrează că „30 de cuvinte de metadata produc citări”.

Demonstrează ceva mai util:

> **un exact match poate oferi evidență puternică pentru atribuirea textuală, dar observația sursei și demonstrarea mecanismului sunt două lucruri diferite.**

Metadata merită scrisă corect pentru că face parte din document, descrie pagina și este folosită de search engines și alte sisteme. Dar optimizarea serioasă pentru AI nu trebuie construită pe presupunerea că există o formulă publică prin care un anumit câmp produce automat citarea.

Pentru AI Visibility Lab, valoarea studiului este metodologică: **măsoară ceea ce se vede, etichetează inferența și nu transforma o corelație într-un mecanism algoritmic.**

## Întrebări frecvente

### Metadatele pot apărea în răspunsuri AI?

Da. Studiul de caz documentează o reproducere textuală a unei formulări publicate pe delamatescu.ro. Totuși, acest lucru nu demonstrează că meta description este un factor direct de citare sau că toate motoarele procesează metadata în același mod.

### Ce este o frază-trasor?

Este un marker experimental: o formulare distinctivă publicată într-o locație controlată pentru a testa dacă reapare ulterior într-un răspuns. Un exact match oferă evidență mai puternică decât o parafrază, dar nu identifică singur ruta tehnică prin care sistemul a obținut textul.

### Există o limită de 60 de caractere pentru title și 155 pentru meta description?

Nu. Google spune că nu există limite fixe pentru aceste câmpuri. Title link-urile și snippets sunt trunchiate după nevoie în rezultatele Search.[^google-title][^google-snippet]

### JSON-LD ajută AI-ul să înțeleagă o persoană sau un articol?

JSON-LD oferă informații machine-readable despre entități și relații și poate ajuta Google să înțeleagă pagina. Nu există însă o garanție publică că `Person` sau `Article` JSON-LD determină citarea într-un sistem AI.[^google-structured][^google-sd-policies]

### Dacă `curl` vede doar metadata, înseamnă că ChatGPT vede doar metadata?

Nu. `curl` arată HTML-ul primit de requestul respectiv. Pentru proiectele Lovable React + Vite vechi, documentația Lovable spune că URL-urile publice sunt pre-randate pentru search engines și AI crawlers.[^lovable-seo]

### OpenAI recomandă un anumit câmp metadata pentru citarea în ChatGPT?

Nu în documentația publică verificată la 10 august 2026. OpenAI recomandă accesul OAI-SearchBot pentru ca site-ul să poată fi descoperit, afișat și citat clar în ChatGPT Search, dar nu publică un ranking al câmpurilor metadata.[^openai-publishers]

## Metodologie și niveluri de certitudine

### Observația proprie

Cazul delamatescu.ro este un studiu pe un singur subiect și nu are grup de control suficient pentru a demonstra cauzalitatea.

Faptul relevant furnizat de observația originală este exact match-ul dintre textul publicat și textul citat de sistemul AI.

### Sursele externe

Pentru verificarea din **10 august 2026** au fost folosite cu prioritate surse primare:

- Google Search Central;
- Lovable Documentation;
- OpenAI Help Center;
- Perplexity Documentation.

### Nivelurile folosite în articol

**Observație directă** — ceea ce a fost măsurat sau capturat în cazul propriu.

**Fapt documentat extern** — afirmație susținută de documentația oficială a providerului.

**Inferență** — concluzie rezonabilă din observații, dar care nu este prezentată ca mecanism confirmat.

**Ipoteză experimentală** — afirmație care trebuie testată înainte de a fi generalizată.
